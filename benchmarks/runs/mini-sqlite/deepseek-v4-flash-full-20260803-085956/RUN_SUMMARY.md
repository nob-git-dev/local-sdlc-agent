## Comparison with the earlier Qwen run

The earlier Qwen project used the exact same `SPEC.md` hash. Both versions
compile and pass their own generated test suites. Running the current
independent suite against both produced the following result:

| Measure | Qwen run | DeepSeek run |
|---|---:|---:|
| Own generated tests | 179 / 179 PASS | 140 / 140 PASS |
| Independent suite | collection/API-contract failures; 33 ran, 5 failures, 10 errors | 84 / 84 PASS |
| Strict `ResourceWarning` gate | warnings observed | PASS |
| Independent final product verdict | not recorded in its summary | PASS |

The Qwen failures included incompatible public names and value contracts for
`BTree`, `Result.rows_affected`, lexer token types, file-format constants, AST
nodes, and record-codec functions, plus CLI behavior differences. This does
not isolate model intelligence: the DeepSeek run also used the newer harness,
stronger independent evidence, narrower stage calls, and repair policies
developed after the Qwen run. The defensible conclusion is that the **current
DeepSeek plus current harness configuration** achieved a stronger externally
verified result than the historical Qwen plus historical harness configuration.

## Agent and harness observations

What worked:

- Small proposition-sized generation calls were reliable.
- Independent tests exposed self-consistent but externally incompatible APIs.
- Test provenance rules allowed generated-test defects to be corrected without
  weakening fixed specification evidence.
- Separate review calls prevented the coder from approving its own output.

What still needs improvement:

- Large DeepSeek artifacts often arrived as malformed JSON, fenced
  `BEGIN_FILE` blocks, or truncated patches.
- Two prompts approached the 16,384-token limit too closely; profiles need a
  mandatory input/output safety margin.
- The S06/S07 PM output became repetitive and required stage-plan compression.
- A generated interactive CLI test used a nonexistent helper and required a
  test-provenance correction loop.
- The generic artifact lint incorrectly rejected dataclass field references;
  the harness was fixed using AST-declared class attributes and all 583 harness
  tests then passed.
- A harmless parser probe containing SQL text was conservatively classified as
  a database write. The safety decision was respected and the probe was
  replaced with a safer executable check.

## Autonomy assessment

This run completed the full product scope, but it was not a completely
unattended run. DeepSeek produced the MiniSQLite code and role documents. The
higher-level operator adjusted task size, corrected one generic harness lint
defect, selected safe replacement probes, and assembled final evidence. The
next autonomy target is to make those stage-resizing and evidence-closure
decisions deterministic supervisor behavior rather than external intervention.
